# Changelog

All notable implemented changes to autoFPL are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and releases will use [Semantic Versioning](https://semver.org/) once product releases begin.

## Unreleased

### Changed

- **The prediction roadmap now has an explicit player/source evidence-fusion programme.** Forecasts target appearance, start, minutes, event and FPL-point distributions rather than one player rating; named experts and social sources produce typed claims whose reliability is learned by target and lead time, while the initial squad compares registered 3/6/8-Gameweek rolling horizons.
- **The roadmap now defines future dashboard sharing and owner access.** Sharing is an explicit, revocable and sanitized read-only viewer capability, while an OpenID Connect owner session and backend authorisation gate configuration, collection, selection locking, provider and administrative actions; implementation remains outside the current private single-owner slice.
- **Selection ownership is now a roadmap invariant.** Forecasts and AI may propose changes but cannot apply them: the user edits a draft, explicitly locks an immutable pre-deadline revision, may supersede it before the deadline, and receives only deterministic official substitution/captaincy resolution after the latest lock becomes permanently frozen.
- **Read-only analytics now accept additive database migrations.** Baseline and temporal-feature commands require schema version 7 or newer instead of rejecting the deployed version 9 database solely because later compatible tables exist.
- **Public-page collection now reuses Quark's existing research stack.** The FPL Form operator importer verifies and uses the isolated Playwright MCP service, combines fixed navigation and extraction in one hard-coded code call to avoid a huge accessibility snapshot, parses the large embedded dataset inside that browser, returns only bounded active-Gameweek rows, records transport/extraction and provider-payload identities, and closes its session; autoFPL no longer downloads the 105 MB page into its own container or needs a second browser/scraper stack.
- **The roadmap now specifies the decision-room and player-dossier overhaul.** Official-photo pitch cards lead to a responsive cutoff-aware dossier with forecast distributions, chronological prior-Gameweek outcomes, upcoming fixtures and evidence provenance; the delivery order now includes official photo capture, a typed dossier API, richer temporal features and explicit missing/double-Gameweek states before real forecasts populate the UI.
- **The roadmap now defines a dependency-ordered route to the human-approved advisor.** It identifies the current deployed deterministic checkpoint, the first usable v0.1 single-Gameweek advisory journey, transfer and chip planning horizons, the v1.0 product boundary, critical-path issues and evidence gates without implying that forecasting or advisory product behavior already exists.
- **The v0.1 route is now code-first and home-lab sized.** SQLite persistence and a leakage-safe baseline forecast are the critical path; news/scout/pundit features and Byparr are optional enhancements that must prove out-of-time gain rather than blocking the first prediction.
- **Research controls now apply at the correct stage.** Literature guides candidate selection and exploratory analytics can begin immediately; target/split/baseline registration, final-holdout discipline, calibration, decision utility and reproducibility remain mandatory before a result influences advice.
- **The default architecture is one deployable application backed by SQLite.** Python and a web UI are added only for concrete predictive or product needs; PostgreSQL, separate services, universal contracts and release-grade operational evidence require measured justification.
- **The pre-implementation research-acceptance gate has been removed.** CI no longer needs issue/PR read permissions or GitHub API proof of a second person's acceptance before analytics code can be written.
- **Development quality gates now prioritise correctness and research validity over ceremony.** `dev` requires comprehensive tests, governance and secret scanning while signatures, stale-base reruns and universal blocking on slower analyses are reserved or relaxed as appropriate; `main` remains the strict signed release boundary, and independent review is risk-based.

### Added

- **Public football evidence now has an executable quarantine boundary.** Migration 16 stores immutable, idempotent availability/start/minutes/role claims with source revision, publication/retrieval/availability timing, official player identity, directness, bounded supporting span, extraction identity/confidence and duplicate clustering. A strict bounded operator JSON import and typed cutoff-safe read route expose candidates without letting them influence forecasts or squad state.
- **User selections can now be edited without rewriting history.** A validated edit route accepts a complete XI, goalkeeper reserve, ordered outfield bench and distinct captaincy from the same forecast squad, rejects stale, post-deadline and infeasible changes, and creates a new unlocked immutable revision even when the prior choice was locked. The decision room displays the current user revision on the pitch and provides an accessible swap, captaincy and bench-priority editor; saving never writes to an FPL account.
- **Predicted selections can now become explicit user-owned decisions.** Migration 15 stores immutable, hash-identified selection revisions linked to an exact Baseline v0 artifact; the API idempotently creates a draft, rejects stale or post-deadline locks, records a one-time explicit lock and computes expired/frozen status without rewriting history. The decision room shows the Draft → Locked → Frozen lifecycle, requires a confirmation dialog and repeatedly states that no action is sent to the user's FPL account.
- **Official FPL published expected points now have a standalone evaluator.** A deterministic read-only command selects the latest capture for which the target was the recorded next Gameweek, requires complete deadline-correct forecast/outcome identity, retains zero-minute players, and reports overall/position/zero-minute MAE, RMSE and bias with immutable data/run hashes while remaining unpromoted.
- **Official FPL published expected points are now a point-in-time challenger.** Migration 14 retains optional `ep_next` values inside the exact official capture, enriches unchanged pre-migration captures on re-import, exposes the value in the cutoff-aware player dossier, and displays it beside Baseline v0 with an explicit not-promoted warning; it does not yet drive squad selection.
- **Baseline predictions now have durable artifact identity.** Migration 13 stores one immutable Baseline v0 document and content hash per exact official capture. Startup, explicit official import and background official polling create or reuse the artifact, the advice route is read-only, and the decision room shows its forecast ID and short hash.
- **The decision room now provides an initial real-evidence prediction.** A transparent Baseline v0 scores official players from price, ownership, availability, capture-reported starts/points and fixture context, constructs a budget-, club-, position- and formation-feasible squad with XI, bench and captaincy, and shows wide player intervals with reasons and risks. It is explicitly unvalidated, and the refresh action only reloads the latest persisted forecast while collection continues independently in the background.
- **Official reference snapshots can now be collected automatically.** An optional bounded interval runs the existing fixed bootstrap-and-fixture importer, persists every attempt independently of immutable content deduplication, resumes the remaining interval after restarts, and leaves final-outcome capture explicit until a Gameweek is finished and data-checked.
- **Bounded public-forecast collection can now run automatically.** An optional 60-to-1440-minute instance setting runs the same fixed FPL Form importer inside the single application process, resumes from the persisted last-check time across restarts, treats off-season and bounded collector failures as visible source states, and keeps operator-only collection as the default.
- **Public-forecast readiness is now visible and durable.** Every operator FPL Form check records a bounded captured, provider-waiting or failed result without storing partial predictions or removing an earlier immutable capture. A typed read-only status route and responsive decision-room strip distinguish off-season availability from collector failure and keep the external challenger separate from official FPL evidence.
- **Official underlying statistics now have an executable same-fold feature ablation.** A deterministic read-only evaluator compares the unchanged official ridge/tree contract with fixed rolling-three and exponentially weighted xG, xA, xGC, ICT, BPS and defensive-contribution features on identical players and expanding origins. Nullable-history sample counts remain explicit, ridge preprocessing and tree feature removal stay fold-local, and the report remains unpromoted until repeated out-of-time evidence justifies a model change.
- **Official temporal features now include underlying performance history without faking legacy zeroes.** `official-temporal-v2` adds cutoff-safe latest, rolling 1/3/5-Gameweek and exponentially weighted summaries for retained official xG/xA/xGC, ICT/BPS, influence, creativity, threat, defensive actions and penalty outcomes. Every nullable metric carries its own observed sample count, and the unchanged ridge/tree feature contract remains untouched until a same-fold ablation measures incremental value.
- **Official outcomes now retain underlying performance evidence.** Migration 10 adds nullable legacy-safe storage for official xG, xA, expected goal involvements/conceded, ICT, BPS, influence, creativity, threat, defensive actions and penalty outcomes. New final-outcome imports require bounded values atomically, while the cutoff-safe player dossier and recent-form UI expose the most useful xG/xA/xGC/ICT/BPS/defensive contribution fields without inventing values for older captures.
- **FPL Form forecasts now have an executable model-feature ablation.** A deterministic read-only evaluator compares official-only ridge/tree models with separately named conditional-points and appearance-adjusted variants on identical players and source-complete expanding-origin folds. Fold-local preprocessing, native tree missingness, explicit source/probability indicators, strict cutoff/identity reuse and machine-readable exclusions prevent partial forecast history from creating a favourable comparison.
- **FPL Form predictions now have a model-ready temporal feature boundary.** A read-only Python command selects the latest forecast available by an official feature replay's exact capture time, requires strict direct player/fixture identity agreement, aggregates fixture-level conditional and appearance-adjusted values, preserves missing players and probabilities, and emits deterministic exploratory feature provenance for the next official-only versus scraped-source ablation.
- **A fixed nonlinear temporal challenger is executable.** A hash-locked scikit-learn histogram gradient booster runs on the ridge evaluator's identical expanding-origin folds, retains partial missing values for learned branches, removes unsplittable features using training data only and reports deterministic configuration and fold diagnostics alongside ridge and simple incumbents.
- **The first temporal-feature challenger is executable.** A dependency-free ridge evaluator reconstructs every training and target row from its own pre-deadline official replay, admits only outcome corrections available at the later decision capture, fits median imputation, missing indicators and standardisation inside each expanding-origin fold, and compares total-points MAE/RMSE/bias against fixed simple incumbents. Reports retain fold provenance and coefficient diagnostics and remain explicitly exploratory.
- **The FPL Form external-baseline evaluator is executable.** A deterministic read-only operator command selects the latest deadline-eligible forecast per Gameweek, requires complete authoritative identity resolution, pairs the latest later official outcome and reports immutable data/run identities. It scores published conditional points with zero-minute and position slices while keeping the fixture-level appearance-probability adjustment separately named, measuring missing probabilities, and retaining exploratory unpromoted status.
- **Scraped forecast identity coverage is now executable and fail-closed.** A typed read-only OpenAPI route proves one FPL Form capture against the newest official catalogue that was actually available by forecast retrieval and the Gameweek deadline. Present source IDs must agree with normalized name, club, position, team participation and London-local kickoff; absent IDs may use only unique attribute matches. Conflicts, ambiguity, invalid local times, unmatched rows, future catalogues and post-deadline forecasts are reported explicitly and cannot pass the coverage gate.
- **The first point-in-time player and team feature table is executable.** A read-only Python command selects one official pre-deadline replay, admits only earlier outcome corrections available by that capture time, and writes a deterministic hash-identified artefact containing player lags, rolling 1/3/5-Gameweek statistics, exponentially weighted form, explicit missingness, target fixtures and rest gaps, plus finished-match team attack/defence/result form split by venue. It remains exploratory and cannot populate product forecasts before out-of-time promotion.
- **The decision room now uses official players and portrait cards when real capture evidence exists.** A qualifying cutoff-safe replay supplies a legal 15-player identity preview, club and fixture context, allowlisted Premier League photos and typed dossier links while points, minutes, captaincy and selection remain explicitly synthetic. Selecting any pitch or bench card opens a responsive dossier with prior Gameweek statistics, the next six Gameweeks, evidence and honest missing-data states; URL selection, keyboard/touch controls, portrait fallback and reduced-motion behavior are included.
- **Official player portraits and cutoff-aware dossiers now have a real API boundary.** Official bootstrap photo identifiers are validated, retained and converted only into allowlisted Premier League asset URLs; re-importing identical raw evidence deterministically enriches pre-migration rows. A typed read-only route selects the same pre-deadline official replay, returns player/team/status identity, the five latest prior outcomes available by that deadline, explicit single/double-Gameweek fixture context, and the next six Gameweeks of fixtures while excluding later outcome corrections.
- **A bounded public predicted-points capture is now implemented.** The operator-only FPL Form importer performs one fixed-origin Playwright-MCP extraction; rejects off-season, malformed and ambiguous prediction sets atomically; records immutable availability timing and compressed canonical evidence; normalises fixture-level conditional points and optional appearance probabilities; and exposes only a read-only provenance/count summary. Historical page values are not backdated, and the source remains an unevaluated external baseline until active 2026/27 captures can be scored against later outcomes.
- **Point and minutes distributions now have executable incumbents.** Correction-safe zero, global, position and player empirical distributions are evaluated with CRPS, pinball loss, quantile calibration, central interval coverage/width, sample-size diagnostics and position slices without Gaussian assumptions or 90-minute clipping.
- **Expected Gameweek minutes now have executable incumbents.** The rolling evaluator compares zero, global, position, player-history, last-minutes and pre-deadline official-running baselines with MAE/RMSE/bias and position slices, preserves correction-time chronology, and scores double-Gameweek totals above 90 without clipping.
- **The first probabilistic availability baselines are executable.** The rolling evaluator now predicts whether each player reaches 60 official Gameweek minutes using smoothed global, position, player and pre-deadline official-start rates; it reports Brier score, log loss, descriptive calibration bins, expected calibration error and position slices while preserving correction-time leakage controls and exploratory-only status.
- **The first leakage-safe baseline evaluator is executable.** A dependency-free local Python command reads complete SQLite replay/outcome pairs without writing the database, applies expanding Gameweek origins, excludes outcome corrections unavailable at each target deadline, compares five auditable point baselines with MAE/RMSE/bias and position slices, and emits deterministic hash-identified exploratory reports while failing closed on insufficient or incomplete data.
- **Official per-player Gameweek outcomes now complete the replay data path.** A bounded fixed-origin operator command fails closed until the official event is finished and data-checked, all Gameweek fixtures are final and player IDs exactly cover the reference capture; exact raw bytes and normalised outcomes are stored immutably, exposed through typed read-only OpenAPI routes and paired only with a complete cutoff-safe replay.
- **The decision room reports outcome readiness.** Its official-data footing now distinguishes an awaiting final result from a fully player-matched replay/outcome pair without presenting the still-synthetic forecast as real advice.
- **Official FPL captures can now be selected as leakage-safe pre-deadline replays.** A typed OpenAPI route chooses the newest immutable capture whose retrieval-time availability is no later than that capture's recorded Gameweek deadline, returns the exact content identities and lead time, and excludes later corrections.
- **The decision room now shows its real-data footing.** A responsive capture-to-deadline provenance tape reports official player/fixture counts and replay readiness while keeping the synthetic forecast fixture visually and verbally separate.
- **The first real point-in-time source capture is executable.** A fixed-origin operator command retrieves the public official FPL bootstrap and fixture resources without credentials, redirects or caller-controlled URLs; bounds time, concurrency and response size; validates and atomically stores exact private JSON, hashes, retrieval-time availability and normalised Gameweek/team/player/fixture rows; deduplicates identical content; and exposes only a typed latest-capture summary through OpenAPI.
- **The supported HTTP surface now has a generated OpenAPI 3.1 contract.** `/openapi/v1.json` publishes stable operation IDs, tags, summaries and response schemas for the private API; contract tests verify important paths and reject representative secret-bearing terms, while the patched OpenAPI.NET dependency line preserves the repository's vulnerability gate.
- **The first Gameweek decision-room product slice is executable.** The .NET application now serves a responsive formation and bench, interactive player evidence cards, explanation and risk panels, alternative strategies and a grounded-conversation area from a typed, explicitly synthetic advice endpoint. The UI cannot be mistaken for a fitted forecast and keeps AI disabled until real evidence and a supported MCP or server-side provider path exist.
- **The product roadmap now starts with the user experience and defines the complete AI/research route.** v0.1 connects the decision room to SQLite snapshots, real point-in-time data, calibrated forecasting, CPU/GPU-parity Monte Carlo scenarios, feasible alternatives and equivalent ChatGPT/Codex plugin, generic MCP and optional server-provider access. It explicitly separates a ChatGPT-hosted subscription experience from API-key-funded inference in the standalone site.
- **Current manual evidence now has an executable timing and interpretation contract.** A versioned catalog inventories every field accepted by all eight POST routes, separates decision state from observed-event and outcome evidence, forbids backdating replay availability before receipt, and is enforced against the .NET request DTOs without changing payloads, adding persistence or logging request bodies.
- **Manual effective-outcome scoring is now deterministic executable product behavior.** A fail-closed endpoint composes the existing substitution and captaincy outcome with one complete manually supplied integer-points snapshot, excludes unused bench points, applies the normal captain multiplier and returns immutable wide-integer totals without deriving scoring events, chips, external retrieval, forecasting, simulation or account actions.
- **Effective gameweek outcomes now compose existing deterministic rules.** A single fail-closed endpoint applies automatic substitutions and captain/vice fallback to the same valid complete selection and manually supplied play evidence, returning one internally consistent immutable result without scoring, status retrieval, persistence or account actions.
- **Automatic substitutions are now deterministic executable product behavior.** A fail-closed endpoint composes a valid complete gameweek selection with manually supplied play evidence, applies goalkeeper and bench-priority substitution rules without breaking the existing formation constraints, and reports activated substitutes and unresolved starters without status ingestion, scoring or account actions.
- **Effective captaincy is now deterministic executable product behavior.** A fail-closed endpoint composes a valid complete gameweek selection with manually supplied player-minute evidence, retaining the captain, promoting the vice-captain, or returning no effective captain according to the current official rule without status ingestion, substitution execution or scoring.
- **Complete manual gameweek selections are now executable product behavior.** A fail-closed endpoint composes the existing squad and starting-XI rules with a replacement goalkeeper and three ordered outfield substitutes, preserving bench priority without FPL account access, appearance data, substitution execution or scoring.
- **Starting-XI feasibility is now executable product behavior.** A manual-input API endpoint validates that 11 unique starters belong to a valid squad, satisfy current 2026/27 goalkeeper/defender/forward formation rules, and have distinct captain and vice-captain selections from the XI.
- **Manual squad feasibility is now executable product behavior.** A new API endpoint applies deterministic 15-player composition, unique-player, club-limit and exact integer-tenths budget rules without external FPL access or account automation.
- **Initial source records now have an executable provenance contract.** A Draft-07 schema binds manual input and repository-authored synthetic fixtures to source identity, purpose and point-in-time metadata; checked-in examples are enforced without adding runtime ingestion or persistence.
- **The verified development API is privately deployed through Dockhand.** The Git-backed Compose stack pins the published GHCR manifest digest, runs with a read-only root filesystem and bounded resources, and exposes the service only on the trusted internal Docker network with no host port, proxy host or public DNS route.
- **A bounded private-development API and hardened container artifact are available from `dev`.** The service exposes liveness, readiness, decision-snapshot metadata validation and deterministic manual squad validation; rejects malformed, ambiguous and oversized requests; runs non-root in a digest-pinned chiseled image; and is built, scanned, smoke-tested and published by protected CI without external FPL access, persistence, providers or account automation.
- **Documentation now has a maintained standard and index.** Repository claims must be grounded in code, contracts, deployment definitions or versioned evidence; planned work is separated from implemented behaviour; safety, research and human-approval boundaries are required where applicable; and CI checks local documentation links.
- **The project roadmap now states priority outcomes and evidence gates.** It covers the private development service, prediction-quality data ingestion, authoritative rules, forecast research, simulation and optimisation, advisory interfaces, human approval, and release hardening without promising dates.
- **Decision-snapshot metadata has a versioned JSON contract.** The `1.0` schema, examples and .NET contract model enforce canonical source types and reject schema drift before snapshot metadata can enter later decision workflows.
- **The public repository foundation is governed and reproducible.** Branch/release policy, proportionate security boundaries, engineering and research standards, threat modelling, dependency controls, architecture decisions and executable repository-policy tests establish the constraints for later product work.
